# beer-game セキュリティポリシーレビュー

このSkillは、beer-gameプロジェクトで2026-08-02までの議論を通じて確立したセキュリティ方針を、コード変更のたびに一貫して適用するためのチェックリストです。汎用的な脆弱性スキャンではなく、**このプロジェクトが下した設計判断に沿っているか**を確認することが目的です。網羅的な脆弱性診断が必要な場合は、汎用の `security-review` スキルも併用してください。

## 前提となる方針（詳細は `[[security_posture]]` メモリ参照）

- ソースコードが公開されていること自体は、秘密にすべきロジックがない限りリスクが低いという前提に立つ（security through obscurityに頼らない）
- 一方で、認可(authorization)の実装不備・シークレットの誤コミット・従量課金インフラでのコスト濫用は実害の大きいリスクとして重点的に見る
- フロントエンド（GitHub Pages想定・静的）とバックエンド（Cloud Run想定・API）は分離構成。バックエンドのみがアタックサーフェスと課金対象になる

## チェックリスト

変更されたファイル・エンドポイントごとに以下を確認する。

### 1. 認可(IDOR)チェック — 最優先
- 新規または変更されたエンドポイントが、URLパスやリクエストボディで `game_id` / `user_id` などのIDを受け取っているか
- 受け取っている場合、**そのIDが呼び出し元の所有物であることを明示的に検証しているか**（推測困難なUUIDであることに依存していないか）
- ユーザーアカウント機能が入った後は特に、「他人のIDを指定したら弾かれるか」を具体的なテストケースとして書けているか

### 2. 本番環境での情報露出
- `BEER_GAME_ENV=production` で `/docs` `/openapi.json` `/redoc` が無効化される既存の仕組み（`app/main.py`）を壊していないか
- 新しいエラーハンドリングがスタックトレースや内部パスを本番レスポンスに漏らしていないか

### 3. レート制限・コスト濫用対策
- 新規エンドポイントが `app/rate_limit.py` の `rate_limit` 依存関係でカバーされているか（`APIRouter`の`dependencies`に含まれるルーター配下か）
- 計算コストの高い処理（大量ループ、外部API呼び出しなど）を認証なしで誰でも呼び出せる状態にしていないか。Cloud Run等の従量課金インフラでは、これがそのままコスト増に直結する

### 4. リソース上限
- 新しい永続化ストレージ（インメモリ・DB問わず）が、`GameStore`のFIFO上限（`_MAX_STORED_GAMES`）と同様に、無制限に増加しない設計になっているか

### 5. シークレット管理
- APIキー・DB接続情報・トークンなどがコードやコミット履歴にハードコードされていないか
- 新しい機密情報は `.gitignore` 対象になっているか（CLAUDE.mdのルール通り）

### 6. CORS
- `allow_origins` がワイルドカード(`*`)でなく、実際のフロントエンドオリジンの明示的な許可リストになっているか

### 7. チャット機能（実装され次第）
- ユーザー生成コンテンツを `dangerouslySetInnerHTML` 等でエスケープなしに描画していないか（Reactのデフォルトエスケープに任せる）
- スパム・迷惑行為対策のレート制限があるか

### 8. 依存関係・CI
- `.github/dependabot.yml` が示すエコシステム（uv/npm/github-actions）のPRが放置されていないか
- 新しいGitHub Actionsワークフローが `pull_request_target` を外部PRのコードチェックアウトと組み合わせて使っていないか（シークレット漏洩経路になる）

## 実行手順

1. `git diff` またはレビュー対象のPR差分を確認し、上記チェックリストの各項目に該当する変更があるかを洗い出す
2. 該当する項目ごとに、方針に沿っているか・逸脱があるかを判定する
3. 逸脱が見つかった場合は `ReportFindings` ツールで報告する（`category`は該当するチェックリスト項目名を使う。例: `idor`, `info-disclosure`, `rate-limit`, `resource-bounds`, `secrets`, `cors`）
4. 該当する変更がない項目は報告に含めない
